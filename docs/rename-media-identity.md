# 重命名沿用已确认的作品

订阅下载的资源如果再次按文件名搜索 TMDb，可能匹配到同名片、翻拍版或其他作品。现在重命名优先使用人工指定的身份，其次使用下载文件清单中保存的身份；未建立清单的下载会先主动向下载器核对，只有排除等待中的下载关联后才使用原有自动识别。

## 行为

- 下载追踪保存每个被选中视频的原始相对路径、文件名、大小、TMDb ID 和 `movie`/`tv` 类型。重命名若先于首次轮询到达，会按下载记录的唯一标签查询实际种子和文件列表，不按种子标题猜测。元数据或文件选择尚未就绪时延后处理。暂停加入的种子在保存身份之后才启动。文件有季号时沿用文件里的季号，没有时用订阅季号补足，避免动画的本地季号覆盖 TMDb 季号。
- 本地视频按路径后缀和字节大小核对。STRM 复用生成流程的反向路径解析，并从生成记录取原视频大小；不会把 STRM 文本文件大小当成视频大小，也不会请求其播放 URL。
- 下载快照使用订阅归属、下载器、推送时间、集范围和跟踪信息计算版本。下载 ID 复用后旧版本失效；重新选文件总是完整替换，旧文件绑定不会混入新清单。文件行与快照标记在同一短事务中替换，下载器网络取数在事务之外进行。
- 同一个文件匹配到互相矛盾的身份时停止处理，并提示人工指定。人工绑定按完整源文件路径保存，优先于下载绑定。自动搜索得到的 ID 不会自动升级为已确认身份。
- 下载元数据或 STRM 原视频大小暂未落库时进入按路径合并的自动重试，最多 12 次，间隔从 5 秒退避至 60 秒。等待时不写失败记录、不搜索其他作品；耗尽次数才记录可见原因。停止监控会取消计划，文件暂不稳定或与文件事件并发时也保留下一次重试。
- 指定 ID 的详情请求失败、返回错误作品或缺少作品详情时，不再降级为标题搜索，也不调用 AI；记录失败原因并等待重试。绑定独立落库，失败不会丢失。
- 电脑端、手机端的单条和批量重试均可指定 TMDb ID 与类型，并提供 TMDb 外链供核对。批量指定会把所有选中项绑定为同一作品。接口是异步提交，页面提示“已提交”。
- 升级前已完成、仍能通过 hash/标签在下载器中找到的记录，每轮最多补建 20 条绑定。按游标轮转，暂时取不到清单的记录不会阻塞后面的记录。已误命名的成功记录需要在重命名明细里手动纠正并重试，不会在升级后批量移动。

## 关联的适用范围

上传或挂载时需要保留种子内的文件相对路径及原视频大小。下载器已删种且从未保存过清单、跨链路改写过文件名/目录、旧 STRM 缺少原视频大小等情况，无法可靠回溯下载归属，需要指定 TMDb ID。当前 OpenList 地址和编码设置必须与 STRM 生成时一致，沿用既有路径解析的约定。

数据库升级脚本 `20260815-media-identity-binding.sql` 增加绑定表和重命名失败原因列，`20260816-media-identity-download-version.sql` 增加推送版本列，均已注册到 `MysqlDdl`。绑定不随重命名明细清理而删除，防止重建明细后再次认错作品。

测试跨越真实 `MediaParser` → `TMDbClient`，仅模拟最底层 TMDb API；另覆盖下载文件关联、STRM 大小、身份冲突、人工绑定持久化读取、失败不复制、旧产物清理及两端共用提交参数。

回归测试另覆盖首次轮询前主动关联、失败下载 ID 复用、更换文件选择后的完整替换、完成时补写 hash 不误判快照过期、STRM 记录晚落库后的自动恢复、重试去重/上限/停止监控取消。独立 MySQL 接口验证会检查原子替换失败时的事务回滚及自动恢复。
