跨子包的约定。各子包另有自己的 AGENTS.md。

## NOTES
- **对账「只升不降」，因此每种媒体类型都必须有一个显式的人工降级出口，而且要能被找到**。`SubscriptionService#refresh` 只做 `MISSING/IN_FLIGHT → IN_LIBRARY`，反向不做——一次误删（媒体库扫描抽风、刮削没刮出来、库路径临时挂了，症状都是「这集查不到」）不该触发几十 GB 的重下。代价是用户把文件从 Emby 删掉之后再点「对账」，**状态纹丝不动而日志里一切正常**：那一轮确实跑完了，只是没什么可升级的。降级只能靠 `resetEpisode`，所以它的入口必须显眼——原先只有一个：进度弹窗 →「查看全部集」→ 那一行的「重置」，藏了两层；**电影在这条路上尤其找不着**，它在集表里只有集号 0 那一行哨兵记录，照剧集那套渲染出来是「已入库 1 / 1 集」、一个不可点的集号「0」、外加一个写着「第0集」的按钮，三处都对不上「一部电影」。现在电影在进度弹窗里单走一条分支（一行状态 + 「重置为未入库」），两端卡片的「更多」里也紧挨着「对账」放了一条——用户点完对账发现没反应，下一眼就能看到正确的出口。三条不要改坏的：**判断是不是电影一律看 `mediaType`**（剧集的特别篇也是第 0 季，用 `season === 0` 判会把它一起当成电影，与后端同一条约定）；**重置必须打到集号 0**，传别的集号会「重置成功」但一行都没改到、页面仍显示已入库，与这个入口本来要修的现象一模一样；**收尾刷进度前要判 `currentSubscription?.id === 操作的那条`**，弹窗点遮罩就能关，理由与「一键补齐全部」那条完全相同。`composables/__tests__/usePtSubscription.spec.ts` 钉住这三条。
  **同一个洞在 `IN_FLIGHT` 上又开了一次，而且更隐蔽**：种子下完了、文件也确认在种子里，卡住的是上传网盘/STRM/刮削那一段（用户手动删掉那条同步任务是最直接的一种），集就永久停在「在途」。三条路全部走不通——对账只升不降碰不到它；`StuckEpisodeSweepService` 对 `file_confirmed` 的集**只告警、永不退回**（那是对的，重下解决不了上传问题，还要白背一份 H&R 义务）；而重置按钮此前只在 `IN_LIBRARY`/`BLOCKED` 时渲染。于是这类集在界面上**一个出口都没有**，用户看到的是一条写着「在途」、实际什么都没在下、也点不动的记录。后端 `resetEpisode` 从来不限状态，缺的只是那个按钮，现在 `IN_FLIGHT` 也渲染（电影同理，两端的进度弹窗与卡片「更多」四处）。两条边界：**`UPGRADING` 刻意不给**——重置一律置 MISSING，而洗版中的旧版本还在库里，置 MISSING 会让它被当成缺集从头重下一遍，正确的取消是退回 IN_LIBRARY；**在途的确认框要多写一句「不会删下载器里的种子或已下好的文件」并指向「同步任务记录」页**，那批集的文件多半已经躺在硬盘上了，用户最先担心的就是这个，而真正该去的地方是上传那条链路。
- **日志里提到订阅/剧集，一律用 `PtLogText`（`pt/PtLogText.java`），不要只打 id。** 改造前 40 处写的是 `订阅[148]`，而库里有 191 条订阅——没有任何人能从 id 认出那是哪部剧。最刺眼的一处在 `StuckEpisodeSweepService`：上一行刚把 `title` 取出来喂给通知（通知里是《闪耀的她》），紧挨着的 `log.info` 仍然只写 `订阅[148]`，而那条 INFO 恰恰是要用户去「复制记录」页动手的。`EmbyClient` 更彻底，一屏 `未找到 tmdbId=281281 的剧集`。三条：
  1. **`PtLogText` 是 `PtNotifyText` 的日志侧对应物，两者不能互相复用。** 后者按 TG 的 HTML parse_mode 写、所有动态内容都过了 `escapeHtml`，直接拿来记日志会把 `Tom & Jerry` 写成 `Tom &amp; Jerry`，而 `&` 在片名和组名里相当常见。反过来 `PtLogText` 不转义，也就绝不能拿去拼通知。
  2. **格式是 `《剧名》 S01E05[#148]`——名字在前，id 退到方括号里但必须留着**：读日志的人经常要拿 id 去查库或拼接口地址，剧名干不了这件事。标题为空时写「《未命名》」而不是让 StringBuilder 拼出字面量「《null》」（后者看着像代码 bug，会把人引到错的方向）。手里确实没有订阅对象时用 `PtLogText.subject(Integer)` 渲染成 `订阅[#148]`——**它的意义是让「这里确实没有名字」变成显式的**，不是给「懒得去查」开的口子。
  3. **手里只有 id 且加载订阅不划算时，就保持 `订阅[#id]`，不要为一条 DEBUG 多打一次库。** `UpgradeScanService` 的「已达目标质量」就是这种情况（那是最常见的分支，而订阅在下面几行才加载）。
  `EmbyClient` 的「查不到这部剧」已上移到 `SubscriptionService#reportLibraryCoverage`：那里拿得到标题，判据（这条订阅要的集一个都没入库）也比剧条目在不在更贴近用户关心的事。**不要把它挪回去**——接口 `IMediaServerClient` 只收 tmdbId，为一条日志给它加 `title` 参数会波及 25 处测试，而那本来就不是接口该关心的事。
