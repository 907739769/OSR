# STRM 生成设置

全局配置与任务级覆盖的合并规则。

> 本文件由根 `AGENTS.md` 拆出，只在改到本目录时才载入。全局约定（分层、命名、异步包装、日志纲领）仍在根 `AGENTS.md`。
> 新增本域的踩坑记录写这里，不要往根 `AGENTS.md` 里塞。

## NOTES
- **STRM 生成的「输出根目录 / 是否下字幕 / 最小体积」可按任务覆盖**，存在 `openlist_strm_task.strm_override`（JSON），合并规则见 `StrmSettingsFactory`——照 `pt_subscription.filter_override` 的约定，只有出现在 JSON 里的键才覆盖，该列为空时行为与引入前完全一致。两条不要改坏的约定：
  1. **`strmDir`/`strmOneFile` 按路径反查任务，不要改成让调用方传任务**。半数调用方手里根本没有任务对象（`AsynHelper` 的复制完成触发、`CopyRecoveryTask` 的兜底恢复、TG 的 `/strm <路径>`），它们退回全局配置就会让同一目录因「谁触发的」而输出到不同根目录，长出两棵 STRM 树，一致性检查还会把其中一棵报成孤儿。匹配走 `pickCoveringTask`：落在路径分隔符上、取最长（最具体）的任务、停用的任务照样参与。
  2. **URL 编码开关与视频/字幕扩展名刻意不可覆盖**。encode 有三个解码侧消费者（`RenameOrphanScanServiceImpl`、`RenameCleanupService`、`StrmSourcePathResolver` 都要从 .strm 内容反解回网盘路径），扩展名是 `sys_config` 里的全站清单（`MediaExtensionProvider`）；两者都是「播放器吃什么」的全局属性，分库配置只会制造解不开的历史数据。
- **同步遍历必须跳过「Transmission 删种临时目录」，且复制失败时要先问一句「源还在不在」**。Transmission 删本地数据不是就地删：`tr_torrent_files::remove()`（libtransmission/torrent-files.cc）先建临时目录、把内容整个挪进去，再在里面删、最后删临时目录本身——`auto tmpdir = tr_pathbuf{ parent, '/', tmpdir_prefix, "__XXXXXX"sv };` + `tr_sys_dir_create_temp(...)`，`tmpdir_prefix` 是种子名，`__XXXXXX` 是 `mkdtemp` 模板（六个 X → `[A-Za-z0-9]` 随机字符）。默认规则 `.+__[0-9A-Za-z]{6}` 就是照这个模板写的，不是估的；「先挪进去」也解释了为什么临时目录里还套着一层同名真目录。**qBittorrent 是就地删，没有这个行为**，所以只有挂 Transmission 的下载/保种机会撞上。这个目录通常只活几秒，但 `syncOneDir` 的遍历撞上一次就是完整一串坏事：当成新剧集目录 → 在**网盘**上建出同名空目录（永久垃圾）→ 给里面的视频文件提交 `fs/copy` → 复制途中源被删光 → AList 任务转 `state=7` → 留下一条 `copy_status='2'` 的失败记录 + 一条告警，而这条记录**永远重试不成功**（源已经不存在了），`retryAllFailed` 会一遍遍捡起它。实际撞到过：`/download/osr/剧集/2026/Star.Wars...-ADWeb__kefDJG/Star.Wars...-ADWeb`。两道防线都要有，缺一不可：①`OpenListHelper#isTransientDir` 按名字跳过（遍历时它和真目录**没有任何其它可用区别**——大小、时间、内容全是真的，判据只能是名字；规则走 sys_config `openlist.copy.transientdirs`，逗号分隔正则、整体匹配，做成配置而不是写死是为了 Transmission 改模板或链路上换别的会留临时目录的工具时不必等发版）；②`CopyHelper#discardIfSourceGone` 在 `state=7` 时探一次源文件，确实没了就**删记录而不是记失败**。第二道防线是通用的（覆盖任何"复制期间源消失"，不依赖认得出临时目录的名字），`AsynHelper` 的批量/单文件两处与 `CopyRecoveryTask#resolveOne` 三处口径必须一致。**探测里「AList 说找不到」与「AList 不可达」必须分开**：AList 的业务错误走 HTTP 200 + 响应体 `code!=200`，网络不通时 `getFile` 返回 null；把 null 也当成"源没了"，一次网络抖动就会把一批本该保留、可重试的失败记录静默删光（口径同 `CopyRecoveryTask#probeDst`）
- **按记录重试不许走去重入口，也不许靠「先把状态改成失败」绕过去重**。`CopyServiceImpl#syncOneFile` 与 `StrmServiceImpl#strmOneFile` 开头的 `existsCopy`/`existsStrm` 是给外部事件准备的（回调、目录监听、复制完成触发会对同一文件推好几次），而重试是用户明确指定了「就是这一条」，本来就不需要去重。旧实现为了让去重放行，先把记录写成失败再重跑，于是重试期间记录显示成红色的失败，而「源不存在」「体积低于阈值」「提交失败」几条提前 return 的分支会让它**永远停在失败、没有任何原因**。现在两边都拆成「去重入口 + 执行层」（`doSyncOneFile` / `generateOneFile`），重试直接调执行层。复制侧另有四条不要改坏的：
  1. **去重顺带挡着并发，拆开后由 `claimForRetry` 接手**：条件更新 `copy_status IN ('2','4') → '1'`，影响到行才执行。页面连点两下、TG 的 `retryAllFailed` 与页面重试撞在一起时只会提交一个复制任务，`CopyServiceRetryTest` 钉住这条。
  2. **认领必须在信号量内、真正执行前做，绝不能在入口批量预置成处理中**。超过 20 条的重试要在 `COPY_SEMAPHORE` 上排队，提前变成处理中且没有任务 ID 的记录过了 3 分钟宽限期会被 `CopyRecoveryTask` 当成无主记录接管，两条链路抢同一条记录。代价是排队中的记录在页面上仍显示失败，这是有意的。
  3. **执行层对带 id 的记录，每条提前返回的分支都要收尾**：源确实不存在就删记录（同 `CopyHelper#discardIfSourceGone`），OpenList 无响应、体积不够、提交失败都退回失败——**无响应与源不存在必须分开**，理由同那条探测规则。外部事件入口的新文件没有记录，这些分支照旧什么都不写。
  4. **可重试状态只有一份：`CopyServiceImpl#RETRYABLE_STATUSES`（失败 2 + 监控超时/任务丢失 4）**，页面重试、`retryAllFailed`、前端 `useCopyRecord#canRetryCopy` 三处口径一致。处理中与已成功的记录后端直接拒绝，前端不渲染重试按钮；漂移的表现是「按钮能点、点了报错」或「该重试的记录没有按钮」。`retryCopy` 返回实际提交条数，批量重试的提示据此说出跳过了几条。
  STRM 侧不做认领：生成是本地写文件、很快结束，`StrmHelper#addStrm` 本来就按 path + fileName 写回同一行；已成功的记录重试照样重新生成，用于 OpenList 地址或编码配置改过之后刷新 .strm。
- **同步 / STRM 记录的 `fail_reason` 是 `FieldStrategy.ALWAYS`，状态与原因必须一起写**（20260795）。默认的 NOT_NULL 策略会跳过 null，一条失败后重跑成功的记录经 `updateById` 写成成功时旧原因原样留在库里，页面上出现「成功，原因：OpenList 复制任务失败」。ALWAYS 的代价是**任何按实体更新这两张表的地方都要带上当前原因，没带就是清空**：`AsynHelper#updateCopyStatus`、`CopyRecoveryTask#markStatus`、`CopyServiceImpl#markRetryFailed` 都做成了三参数（成功传 null），`claimForRetry` 认领后要把对象上的原因也清掉，否则后面的 `updateById` 会把旧原因写回去。`file_size` 刻意保持默认策略：单文件 STRM 生成拿不到大小，不能拿 null 把目录级生成采集到的值抹掉（`StrmHelper#addStrm` 更新已有行时干脆不 set 它）。`CopyFailReasonTest` 直接检查 MyBatis-Plus 生成的 SET 片段钉住这两条——mock 掉 service 的单测看不到更新策略。
  **复制侧的原因文案只有 `helper/CopyFailReason` 一份**，内存监控链、重启兜底、按记录重试三处共用：同一种故障（OpenList 重启弄丢任务）会从不同链路落进来，各写一份文案用户会以为是两件事。state=7 的原因取 OpenList 任务详情里的 `error` 字段，那是最准的解释（多半是目标网盘报错）。批量提交 `fs/copy` 整批失败时**不落记录**是原有语义、没有改，那种情况原因只在日志里。
- **STRM 生成记录表里也存着字幕记录，任何「按记录重新处理」都必须按扩展名分流**（`StrmServiceImpl#retryOneFile`）。.strm 的文件名是「去掉扩展名 + .strm」，不判类型的话重试 `a.srt` 会写出 `a.strm`、内容指向字幕，**正好覆盖同目录 `a.mkv` 的 .strm**——那个视频从此播不了，字幕记录还被标成成功，页面上看不出任何异常。视频走 `generateOneFile`，字幕走 `downloadSubtitleOneFile`，其余类型（多半是改过扩展名配置）记一条说明原因的失败。`generateOneFile` 自己也要判一次是否视频：按路径触发的入口（复制完成、TG 指令）同样可能递进来字幕路径。
- **内存复制监控对「OpenList 无响应」要容忍，对 404 要先看目标文件**（`AsynHelper`）。原先一次无响应就标「未知」并停止监控，可复制任务其实还在跑；404 一律标未知，而 404 最常见的成因（OpenList 重启、用户清掉了已完成任务）多半意味着文件早已复制完。现在：连续 `MAX_CONSECUTIVE_QUERY_FAILURES`（5）轮无响应才放弃，**放弃时不改状态**，记录留在处理中交给 `CopyRecoveryTask`（它对不可达是下一轮再看）；404 走 `resolveLostTask`，目标文件在记成功（单文件路径补生成 STRM，批量路径由收尾的 `finishStrmDir` 统一生成），不在记未知，查目标文件也无响应就继续监控。口径与 `CopyRecoveryTask#probeDst` 一致，**两处改一处的话，同一种故障在重启前后会被判成两种结果**。
- **批量提交复制整批失败要落成失败记录**（`CopyServiceImpl#submitCopyBatch`），原因取 OpenList 返回的 message。原先返回空列表，这批文件不出现在同步记录里、没有重试入口。记成失败（2）不妨碍下次同步自动再试——`syncOneDir` 的已处理集合只认处理中与成功。
- **STRM 增量扫描只跳「叶子目录」，不跳子树**（`StrmIncrementalScan` + `StrmServiceImpl#scan`，20260802）。目录的修改时间只随它<b>直接</b>包含的条目增减而变、不向上传递：新一集放进 `/电视剧/三体/Season 2/`，变的只有 Season 2。按子树跳过会漏掉「已有季里新增一集」这个最常见的情况，所以非叶子目录与根目录每轮照常列，只有快照对得上的叶子目录（上次列过、没有子目录、修改时间原样没变、生成设置指纹相同、里面文件全部处理完）才跳过。它的修改时间在列父目录时就拿得到，这是能跳过它的前提。几条不要改坏的：
  1. **前提是网盘驱动会更新目录的修改时间**，本地存储一定会、网盘不一定，所以按任务开启（`openlist_strm_task.incremental`）、默认关，并按 `openlist.strm.fullscan.days`（默认 7）定期全量兜底。空值和 Go 零值时间（`0001-01-01…`）一律视为不可用、永不记快照。
  2. **只有定时执行走增量**（`OpenListStrmTask#strm` → `strmTask(task, false)`）。页面「执行」是全量并重建快照；`strmDir`（复制完成触发、TG `/strmdir`、MCP）是 `Mode.FULL`，不读不写快照，与引入前逐字节一致。
  3. **没处理完的目录不能记快照**：写 .strm 失败、字幕查不到（`getFile` 为空时本来就不落记录）、处理异常都会让 `EntryResult.settled=false`，否则下次增量会把这些文件连同目录一起跳过。
  4. **设置指纹**（OpenList 地址、编码、下字幕、最小体积、输出目录、视频/字幕扩展名）变了快照即作废：刚打开下载字幕或调低最小体积时，已跳过的目录里就有「按新设置该生成」的文件。
  5. **快照清理只能在全量之后做**（`purgeStale` 按 `scanned_time`）：增量跳过的目录本来就不会被确认，拿增量的结果去清会把它们全删掉。快照写失败只打 WARN、不影响生成——缺快照的目录下次照常列，是安全方向。
  6. `last_full_scan_time` 只由扫描写（单列 update，不用整实体 `updateById`），编辑接口会把前端带来的值置空，理由是弹窗里带着打开那一刻的旧值。
